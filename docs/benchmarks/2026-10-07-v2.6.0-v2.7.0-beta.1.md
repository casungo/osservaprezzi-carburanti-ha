## Interpretation

This run compares v2.6.0 at 119610b with the 2.7.0-beta.1 integration at e0881b7.
HA is 2026.9.4; both versions use the recorded image ID, two CPU quota and 1 GiB memory.
There are two fresh runs per version, ten operation samples per run, five reloads per
run and one preserved-profile upgrade. Values in the table are medians across runs.

- Real registry cache reduction is 24.5%, compared with 30.5% in the separate synthetic benchmark. Decoded station content agrees.
- Actual next-change property reads take 149.97 versus 6.36 ms per 1,000 pairs per loaded entity, about 23.6 times faster. This isolated workload does not imply the same gain for full refresh.
- Registry search is 28.0% faster in this scenario. The complete four-station refresh remains about 8 seconds with production request pacing enabled.
- CSV parsing is 10.4% slower. This is below the provisional performance threshold and should remain visible in later runs.
- The compare service increases from 0.012 to 0.052 ms while the beta adds derived price attributes. The absolute increase is small.
- Recorder totals increase 9.7%. Fresh setup creates 49 versus 53 entities; the four added refresh buttons explain almost all of the difference. On the 49 common unique IDs, rows increase only from 237 to 238. Minute-boundary effects remain a confounder for small differences.
- Post-refresh process RSS is 365.44 versus 369.33 MiB. The baseline's between-run variation exceeds this difference; these runs do not demonstrate a steady-memory improvement. Growth across five reloads is 0.10 versus 0.24 MiB and does not establish a long-running leak result.

No correctness guardrails failed. No performance increase exceeded all provisional
thresholds. Neither statement establishes absence of regressions outside the measured
scenarios or proves production uptime. The upgrade preserved existing entity IDs.

## Validation

Ruff and mypy passed. Unit tests passed with 491 passed and 7 skipped, with 100%
integration coverage. Real HA contract tests passed with 15 passed. Hassfest reported
zero invalid integrations. The latest runner also passed a complete reduced-sample
CLI run, including its source-quality, memory and shared-entity aggregates.

The separate live-network Docker regression passed fresh, lived, upgrade, outage and
recovery. Its existing upgrade lane starts at v2.6.0-beta.1; the quantitative replay
runner separately verified the requested v2.6.0 to v2.7.0-beta.1 upgrade. The live lane
does not supply latency, freshness or recovery-time KPIs for this report.

HACS was not run locally: its standalone validator is unavailable, and the Makefile's
Docker target validates the remote GitHub ref rather than this local report.
